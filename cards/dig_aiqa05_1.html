MCP 插座通了，权限该怎么管？

第5期选择题考了 MCP 的"统一插座"。有同学会追问：插座一通，AI 是不是就能随便动我的文件、发我的消息？这篇把权限问题讲透。

插座通了 ≠ 能乱插

M5-5 里说过，MCP 让 AI 按同一套标准接入各种工具。但协议解决的是"怎么接上"，不解决"接上之后能干什么"——能干什么是你在授权那一刻决定的。你给一个 MCP 服务器授权读写文件夹，它就真的能读写你的文件夹；AI 只是调用方，权限落在服务器身上。

三个实操原则

  • 最小授权：装一个 MCP 服务器前，先看清它要哪些权限。只想让它"读笔记"，就别给它"删文件"的权限；官方或软件方自带的优先，来路不明的第三方慎装。
  • 能撤的授权才算数：装完记得知道在哪撤销。授权不是一次终身，不用了就撤，和给 App 关权限一个道理。
  • 敏感目录绕着走：涉及身份证照片、合同、账本这类文件的目录，先别接给任何 MCP 工具——这和 M4-8 说的"本地优先、入库先脱敏"是同一条思路：风险跟着数据走，数据不给出去就漏不出去。

一句话总结

MCP 给你的是"标准插座"，安全责任仍在你自己手里：装前看清权限、装后能随时撤、敏感数据不接进去。技术越标准，人越要把好门。
