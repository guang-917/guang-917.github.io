AI知识｜M4-4 向量库与相似度：把“语义身份证”存进柜子，按“长得像”来翻｜4/32

前几期给每段话发了“语义身份证”（向量），上期把长文档切成了资料卡。今天讲最后两块拼图：这些身份证存到哪个柜子里？怎么在一秒钟内从几万张里翻出“意思最像”的那几张？这就是向量库和相似度计算干的活。

一句话结论

向量库解决“几万条向量存哪、怎么一秒翻出来”，相似度计算解决“怎么判断两条内容意思像不像”——两者合起来，就是 RAG 里“翻资料”那一步的全部技术底座。

是什么

向量数据库，说白了就是一个专门存向量的仓库，外加一套“按长得像来找”的检索引擎。它和普通数据库的区别一句话讲清：普通数据库查“等于”——比如 WHERE id=5，精确匹配一条；向量库查“最像的前 K 条”（行话叫 top-k），返回一批“意思最接近”的候选。RAG 流程里 AI“先翻资料”，翻的就是这一次 top-k 检索。

主流选择有三个：Milvus（2019 年开源，现为 Linux 基金会旗下 LF AI & Data 基金会毕业项目，功能全、适合大项目）、FAISS（Meta（Facebook）开源的检索算法库，不是完整数据库但速度快，很多工具拿它当内核）、Chroma（轻量级，几行代码就能跑，自建个人知识库最常用的入门款）。

相似度计算，最常用的是“余弦相似度”。你的问题会被转成一个向量，和库里每条资料向量比一比“方向”。

为什么是“夹角”而不是“距离”

把一条向量想成从原点射出的一支箭。余弦相似度不看箭有多长，只看两支箭的夹角：夹角为 0（同方向），得分 1，意思最像；互相垂直，得分 0，不相关。为什么不直接比数字差多少（那叫欧氏距离）？因为一段话长一段话短，向量长短会差很多，但“说的是不是同一件事”只跟方向有关——就像两篇 500 字和 2000 字的文章可能讲的是同一个话题。

为什么快：HNSW 算法

有人会问：几万条向量一条条比，得比到猴年马月？确实，精确比对太慢，所以实际系统都用“近似检索”，目前最主流的算法叫 HNSW（Malkov 与 Yashunin 在 2018 年的论文中提出）。它像给小区画楼栋地图：先看你问的事大概在几号楼，再进楼栋逐户比对，不用全小区跑一遍。牺牲一点点准确率，换几百上千倍的检索速度——这就是它能“一秒翻完几万张卡”的秘密。

生活比方

向量库像图书馆的分类柜：每条资料入库时按“内容方向”归好类。余弦相似度像那位老练的馆员：你不记得书名，只说“我想找讲怎么给旧房子做保温的”，他不会拿书名一个字一个字对，而是凭“话题像不像”从柜子里抽出三五本最对路的递给你。

今天就能用

用 Python 在本机 10 分钟搭一个最小向量检索，亲手看到“按意思找”的效果：

  1. 安装：pip install chromadb（Python 3.9+）；
  2. 新建 test.py，粘贴：import chromadb; c = chromadb.Client(); col = c.create_collection("kb")；
  3. 存三条资料：col.add(documents=["出差住宿可以报销每晚300元","周二例会改到下午三点","公司年度体检安排在11月"], ids=["1","2","3"])；
  4. 按“意思”查询：print(col.query(query_texts=["去外地住宾馆的钱怎么算"], n_results=2))；
  5. 验证：注意你的问题里没有“报销”“出差”这些词，返回的第一条仍然是“住宿报销”那条——这就是余弦相似度在按意思匹配，不是按字面匹配。
